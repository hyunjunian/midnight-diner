# 심야식당 PWA

설치해서 실행하는 전체 화면 식당 운영 게임입니다. 웹 주소는 설치 진입점이며, 설치한 앱에서는 **세로형 인트로 → 전체 화면 식당** 순서로 실행됩니다.

**설치 없이 플레이:** https://rosagkim.github.io/midnight-diner/preview.html

**설치 주소:** https://rosagkim.github.io/midnight-diner/

## 실행과 설치

- Android·데스크톱 Chrome/Edge: 설치 주소에서 **앱 설치하기**, 또는 브라우저의 앱 설치 메뉴를 선택합니다.
- iPhone/iPad: Safari의 **공유 → 홈 화면에 추가**로 설치한 뒤 홈 화면 아이콘으로 실행합니다.
- macOS Safari: **파일 → Dock에 추가**로 실행합니다.
- 일반 브라우저에서는 설치 안내를 표시하며 게임은 설치한 앱에서 시작합니다.
- 전체 화면·세로 방향을 우선 요청합니다. 가로 화면도 지원합니다.

앱을 열면 **720×1280 세로형 2.5D 시네마틱 인트로**를 재생합니다. 새로 생성한 실사풍 장면에 고정된 구도에 음식의 김과 부드러운 장면 전환을 합성했습니다. 첫 거리 장면에만 아래로 떨어지는 적당한 비를 추가했으며, 실내 장면에는 비 효과가 없습니다. 확대·축소·카메라 이동·밝기 흔들림은 적용하지 않습니다. 원본 실사 화면은 포함하지 않습니다. 인물이 자유롭게 움직이는 완전한 3D 영상은 아닙니다.

여성 주인장과 **새 일본어 여성 합성 내레이션·새 한국어 자막**으로 구성했습니다. 참고 영상의 화면·음악·녹음·대사를 사용하지 않습니다. 빗소리·주방 소리·잔잔한 배경음은 직접 합성했습니다. 특정 배우의 목소리를 복제하거나 변조하지 않았습니다. 사용 모델과 제작 출처는 [제작 기록](planning/intro-production.md)에 남겼습니다.

기기가 음성 자동 재생을 막으면 무음으로 시작하며 **소리 켜기**로 들을 수 있습니다. 영상 종료나 건너뛰기 후 게임 화면으로 전환합니다.

## 게임 화면

- 식당 장면이 화면 전체를 차지하며, 스크롤하는 페이지·소개 문구·푸터가 없습니다.
- 상단에 밤·시각·자금·평판과 설정, 하단에 냉장고·메뉴·꾸미기·이야기 도구를 배치했습니다.
- 손님을 누르면 하단 대화창에서 얼굴·프로필과 이야기를 보고 주문을 받습니다. 마지막 대사 뒤에 부엌으로 이동하는 버튼이 나타납니다.
- 재료 25점·손질 25점·불 조절 50점으로 평가합니다. 요리와 밤마다 익힘 지점이 다르고 레벨에 따라 판정이 좁아집니다. 활동 중 45초를 넘긴 대기는 만족도 감점으로 이어지며, 마감 때 영업비가 정산됩니다. 손질은 도구를 누르거나 미는 조작으로 진행하고, 불 조절은 약불·중불·강불과 뒤집기, 초록 구간에서 불 끄기로 판정합니다.
- 손님 대화와 주인장 선택은 별도 대화 화면으로 표시됩니다.
- 재료 구매·메뉴 해금·맡김 차림 선택·장식 구매는 해당 도구 화면에서 진행합니다.
- 마감 정산에서 다음 밤으로 넘어갑니다.

한 밤은 3사이클·9명으로 진행합니다. 각 사이클 세 손님의 메뉴는 모두 다르며, 세 손님을 결제·배웅한 뒤 다음 사이클을 시작합니다. 마감 버튼을 누르면 별도 영업보고에서 매출·팁·자금 순증감, 평판·누적 만족도 변화, 성장 점수·레벨·다음 조건과 새 구매 가능 항목을 확인합니다.

10대 후반–70대 손님 얼굴 24종은 기존 머리·옷·인상을 유지한 부드러운 일본 애니메이션풍 이미지입니다. 따뜻한 식당 배경과 어울리는 색감·채색으로 표현합니다. 캐릭터는 연결된 텍스처 메시로 더 또렷한 호흡과 고개·머리카락의 지연 움직임을 부드럽게 표현합니다. 입 모양은 모든 화면에서 원화 그대로 고정합니다. 한 개의 WebGL 렌더러를 공유하고, 지원하지 않는 환경에서는 정적인 원화를 포함한 기본 동작으로 전환합니다. 플레이어가 바 안쪽의 보이지 않는 주인장인 1인칭 구도입니다. 주인장 아바타·손님 하체·의자를 없애고, 바 건너 손님의 상체만 표시합니다. 대사는 손님을 클릭한 상세 화면과 이야기 창에서만 표시합니다. 장면은 좌우로 드래그하거나 화살표로 둘러볼 수 있고 가게 밖 보기로 외관을 꾸밀 수 있습니다. 가게 밖에는 적당한 비가 아래로 내리며, 실내에서는 창틀 사이 유리 너머에만 움직이는 비가 보입니다. 동작 줄이기 설정에서는 비 움직임을 멈춥니다. 손님 대화창은 직업·나이·스타일과 단골 여부를 보여줍니다. 서로 다른 3일 방문부터 단골이며, 만족도 90 이상 손님은 방문 때보다 레벨이 두 단계 오른 뒤 재방문 대상이 되며, 만족도와 관계가 좋을수록 재방문 확률이 높아집니다. 한 밤에는 얼굴이 중복되지 않으며 새 손님을 계속 배정합니다. 24종 얼굴을 순환하는 새 방문자에게는 별도 이름과 방문 기록이 부여됩니다. 단골에게는 조리 전 달걀 곁들임을 한 번 서비스할 수 있습니다.

음식은 모두 다른 이미지가 있는 100종입니다. Lv.1은 3종으로 시작하며 Lv.2–33은 레벨당 새 요리 3종, Lv.34는 마지막 1종이 열립니다. 메뉴 수첩은 전체/현재 가능/레벨별 필터와 이름 검색을 제공하며 미래 메뉴는 흐린 이미지와 해제 레벨로 표시합니다. 다음 레벨에 열리는 음식과 가구의 실제 배치 모습을 미리 볼 수 있습니다. 레벨은 성장 점수·평판·누적 만족도 조건을 모두 달성하면 오르고, 달성한 레벨과 이전 구매는 유지됩니다. 추천 메뉴도 주문 편중을 막는 순환 규칙 안에서 선택됩니다.

꾸미기 14종에는 가구별 전용 위치가 있습니다. 구매하면 해당 매장 안팎으로 시점을 옮기고 놓이는 동작과 빛나는 효과, 배치 장소 안내를 보여줍니다. Lv.20 냉장고는 기존 냉장고 자리만 깨끗한 아이보리 제품으로 교체하며 재료 구매가 10% 할인됩니다. 재료 27종도 식당에 어울리는 별도 그림을 사용하며, 해당 재료를 처음 쓰는 메뉴의 레벨에서 구매와 선택이 열립니다. 이전에 가진 미래 재료는 버리지 않고 잠긴 재고로 유지합니다. 자유 배치는 지원하지 않습니다.

이야기는 6가지 사건을 순환하며 사건당 첫 선택과 후속 선택 두 단계로 진행합니다. 선택에 따라 자금·재료·관계를 사용하거나 얻고, 다음 밤에 답례와 후일담이 도착합니다. 손님 상세 대사는 주문마다 바뀌며 저장 후에도 해당 주문의 대사는 유지됩니다.


응대 순서는 **착석 → 대화·주문 수락 → 부엌 → 재료 선택·조리 → 음식 제공 → 식사 → 결제 → 인사·퇴장**입니다. 부엌은 냉장고·화구·밥솥·작업대를 누를 수 있는 별도 화면입니다. 냉장실과 냉동실 문을 각각 열어 실제 선반에 놓인 재료를 고르고, 부족한 재료는 한 개씩 채울 수 있습니다.

구운 주먹밥은 밥솥 뚜껑 열기 → 적정량 뜨기 → 두 손으로 세모 빚기 → 기름 선택 → 불 조절·뒤집기 → 김 감싸기 → 담음새로 이어집니다. 100종은 주먹밥·달걀·국/전골·면·튀김·차가운 요리·밥 차림·팬 요리의 조리 경로를 공유하되 필요한 재료와 목표 익힘, 완성 그림이 달라집니다. 접시의 음식을 모두 물리적으로 시뮬레이션하는 방식은 아닙니다.

내어놓으면 주문한 손님 앞 바 위에 음식이 놓이고 식사 동작이 이어집니다. 약 9초의 활성 플레이 뒤 별점과 금액이 뜨며, 사용자가 눌러야 자금·만족도·성장이 반영됩니다. 현금이 자금 표시로 날아가며 숫자가 적립되고, 마지막 인사를 마쳐야 자리가 비워집니다. 손으로 빚은 그릇은 기존 찬장 부분을 직접 편집한 배치 이미지로 교체합니다.

## 오프라인과 저장

서비스 워커가 앱 화면·게임 코드·아이콘·인트로 전체를 함께 저장합니다. 설정에서 **오프라인 실행 준비 완료**를 확인한 뒤에는 인터넷 없이 다시 실행하고 영상을 볼 수 있습니다. 영상 탐색을 위한 HTTP 바이트 범위 응답도 지원합니다.

진행은 이 기기의 localStorage v7 키에 저장합니다. v2–v6의 진행을 읽어 자금·구매·메뉴·재고를 유지합니다. 조리 중에는 완료한 단계와 선택 재료를 복구하고 진행 중이던 손동작/불 조절 단계만 다시 시작합니다. 제공·결제 대기·배웅 상태도 저장하며, 이전 버전에서 이미 받은 음식값은 다시 지급하지 않습니다. 다른 기기와 동기화하지 않으며, 운영체제나 사용자가 앱 데이터를 삭제하면 저장도 지워질 수 있습니다.

업데이트는 새 파일들을 모두 저장한 뒤 준비됩니다. 설정의 **새 버전으로 다시 열기**로 진행을 저장하고 전환합니다. 플레이 도중 강제로 새로고침하지 않습니다.

## 로컬 개발

빌드나 게임 실행용 패키지는 필요하지 않습니다.

```sh
python3 -m http.server 8000 --directory docs
```

Chrome/Edge에서 http://localhost:8000 을 열고 앱으로 설치합니다. 서비스 워커는 HTTPS 또는 localhost에서만 동작합니다.

| 파일 | 역할 |
| --- | --- |
| `docs/index.html`, `docs/style.css`, `docs/kitchen.css` | 전체 화면 게임·대화·부엌·설치·영상 화면 |
| `docs/cooking-rules.js`, `docs/kitchen.js` | 조리 경로와 냉장고·도구·불 조절 상호작용 |
| `docs/engine.js` | 재고·경제·조리·손님·평판·저장 검증 |
| `docs/game.js` | 게임 입력·화면·세로 인트로 재생·기기 저장 |
| `docs/morph.js` | 호흡·머리카락의 연속 메시 모핑·공유 WebGL 렌더러 |
| `docs/scene.js` | 캐릭터 동작·말풍선·매장 이동·장식 배치 |
| `docs/pwa.js` | 설치·앱 실행 구분과 업데이트 |
| `docs/manifest.webmanifest` | 앱 이름·아이콘·전체 화면·가로 방향·범위 |
| `docs/sw.js` | 오프라인 앱 저장과 영상 바이트 범위 응답 |
| `docs/assets/opening-portrait.mp4` | 새 실사풍 세로 시네마틱, 새 여성 내레이션·직접 합성한 사운드·새 자막 포함 |
| `planning/game-design.md` | 게임 방향과 구현 범위 |

## 검증과 배포

```sh
node --test tests/*.test.cjs
node --check docs/game.js
node --check docs/pwa.js
node --check docs/sw.js
```

규칙·모핑 연속성·오프라인 영상 응답 테스트 총 26개를 실행합니다. 브라우저에서는 설치 진입 화면, 앱 표시 모드에서의 실행, 실사 재생·종료 전환, 주문·조리·구매, 세로·가로 화면, 오프라인 재실행과 저장 재개를 검사합니다.

GitHub Pages는 `main`의 `/docs`를 제공합니다. 검증 후 `main`에 푸시합니다. 앱 파일 변경 시 `docs/sw.js`의 `VERSION`도 바꿔 기존 설치 앱에 업데이트를 전달해야 합니다. 모든 자산 경로와 PWA 범위는 저장소 하위 경로를 지원합니다.

[기획 문서 목록](planning/README.md) · [원작 조사](planning/research/original-work.md)

재료 화면은 품절과 조리 중 잠금을 구분합니다. 품절 재료는 주문 화면에서 바로 채울 수 있고, 필수 재료를 모두 고르기 전에는 시작 버튼에 아직 필요한 재료 이름을 보여줍니다. 중앙 조명은 원래의 등 하나만 유지하며 장식 구매 시 해당 조명의 온기를 보강합니다. 음식 이미지는 각 칸 여백을 넓힌 버전과 표시 경계 클리핑으로 옆 음식 조각이 섞이지 않게 표시합니다.


조리 화면 v16은 냉장고에서 고른 필수 재료만 하나씩 준비합니다. 양배추·대파 묶음도 도마에는 한 종류씩 나오며, 고기는 칼질하고 된장·육수는 계량합니다. 선명한 애니메이션풍 재료 상태 112장과 메뉴별 조리 상태 800장을 사용합니다. 조리 장면은 주인장의 얼굴·몸통이 보이지 않는 1인칭 시점이며 필요한 손과 도구만 보입니다. 칼을 잡은 채 위아래로 움직여 서로 다른 위치를 자를 수 있고 재료 밖의 드래그는 인정하지 않습니다. 달걀 젓기·기울여 붓기·국자 들어 담기는 동작에 맞는 경로로 진행하고, 마지막 담기가 끝나면 완성 화면이 나옵니다.
