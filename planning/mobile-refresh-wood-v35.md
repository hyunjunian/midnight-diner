# Mobile foreground freshness and walnut interface

The old mobile client revealed its restored page before checking a worker, suppressed checks for 15 seconds, and postponed applying a prepared release while cooking or a dialog was open. Installed mobile apps can retain that document across background suspension, so ordinary navigation cache fixes did not cover this path.

Launch and actual foreground returns now cover stale UI with a full-viewport walnut gate, freeze active play/audio, and fetch a nonce-tagged, no-store `version.json`. Restored `pageshow` and focus fallback supplement visibility events; duplicate notifications coalesce while genuine quick returns each check. A changed release waits for the verified atomic worker shell, saves v11 plus an optional validated per-step cooking checkpoint, and replaces the document with that prepared shell. Update navigation resumes play without replaying the intro. Unchanged releases keep the current view, including open dialogs. An unavailable network permits cached play; save/install failures keep progress in memory with retry/explicit-continue controls.

The worker also bridges the shipped v34 client when its resume check contacts the newly activated worker. Release-specific code keeps its matching cached shell. The release tool generates the marker and SHA256 revisions for all 340 offline files. Installation copies matching previous-cache responses, downloading and verifying changed bytes only, and activates only after complete success. This avoids fetching the unchanged large intro/music for every UI release. The previous cache and offline MP4/MP3 ranges remain supported.

`wood-ui-v35.css` replaces the remaining paper/legacy UI surfaces with the existing walnut texture throughout management, dialogue, stories, reports, settings, preparation, dock and payment. Warm ink and control contrast were checked at 320/393/430px; narrow preparation cards use three columns. Existing real cookware and all food, character and intro assets are unchanged. No recipe photo work was performed.

Validation: 109 Node tests; real-worker legacy-v34 migration and offline reopening; mobile standalone simulation covers delayed startup check, rapid returns/coalescing, modal coverage, two automatic upgrades during a partial rice gesture, persisted-pageshow-only upgrade, stale cold shell upgrade, offline foreground and cold reopening, retained funds/inventory/partial actions, cached media reuse and byte ranges. Startup/browser/standalone/embedded, dock state and dialogue/material browser tests pass. Parallel visual audit covered 24 UI/width combinations plus 30 cooking/completion layouts. Lifecycle browser tests use Chromium mobile/standalone emulation and synthetic visibility/pageshow events, not a physical iPhone or Safari.

Evidence is kept outside the release at `/workspace/work/midnight-diner/v35/`.
