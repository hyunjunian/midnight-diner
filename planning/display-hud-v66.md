# Quiet installed display and responsive HUD

Installed mobile apps request upright portrait on launch/foreground/fullscreen changes where the platform permits it; manifest defaults remain fullscreen, now portrait-primary. No rotate-device prompt, permission explainer or blocking overlay is added. There is no automatic Fullscreen API request on taps: only the existing explicit Settings action invokes it with navigationUI hide. Unsupported or rejected orientation/fullscreen calls are safely handled. Normal browser tabs and installed desktops do not get automatic locking. Existing viewport-fit cover, dynamic viewport sizing and safe-area insets are preserved. iOS home-screen status-bar hiding/orientation enforcement cannot be guaranteed by web configuration; black-translucent is retained as the supported edge-to-edge setting, not misrepresented as a hidden statusbar guarantee.

The guest affinity display is removed from markup/rendering/CSS; saved relationship values and rules are preserved.

Settings is a transparent aged-brass gear on a native walnut frame, placed after the funds/reputation panel in the top HUD row. The generated gear source `/workspace/generated_images/exec-c5ebdb2d-bd27-4db0-8885-c432e508b509.png` is preserved; WebP encoding at384×384 retains alpha outside the gear and in its center hole. The asset is original OpenAI image-generation output for this session. At narrow widths, HUD margins and wallet spacing compact while date/clock sizes and44px interactive areas remain. Long balances may ellipsize on tiny screens; the exact balance remains in its detail dialog. When measured space between the date/time and wallet panels fits the growth panel, it occupies that gap at screen center where possible; otherwise growth stays in the row below. Navigation follows the measured panels.
