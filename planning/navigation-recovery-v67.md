# Cloudflare navigation recovery

The v66 automatic-update URL could fail with Chromium ERR_FAILED on Workers Static Assets. Cloudflare's normal HTML handling redirects index.html to its directory URL. Precache followed that redirect, verified the correct HTML bytes, then preserved the response's redirect history in Cache Storage. Returning that cached redirected response for a navigation whose redirect mode is manual is rejected by Chromium before the page can clean its update query.

`withoutRedirect` reconstructs such responses with the same decoded bytes/status/content headers and no redirect history. Stale wire Content-Encoding and Content-Length are removed when reconstructing a decoded stream. This runs when copying/downloading precache entries and when returning prepared, fresh or offline navigation responses, so existing redirected entries are safe without clearing caches or saves. Hash validation, atomic installation, previous-release support, partial cooking and byte-range media handling remain intact. The normal address is still the same origin/root; app-update/resume-update remain temporary resume flags cleaned by the existing bootstrap.

Regression test tests/browser/cloudflare-updates.cjs reproduces the exact v66 error under a307 index redirect, then verifies v67 clean precache, poisoned legacy cache recovery, stable URL cleanup, preserved54321 funds and completed cooking, offline root navigation and MP4 response206/100bytes. Live domain access was blocked by the agent environment's outbound proxy, so the origin was not claimed directly verified from this environment.
